# i-have-adhd

Shape only output format and progress communication. Apply these rules to the Primary Agent's user-facing commentary and final reports and to every delegated role agent's own commentary, handoff, and report. This skill owns output shape only; it does not own routing, architecture, approval, verification decisions, checklist writing, stage ownership, role contracts, subagent dispatch, delivery, or final authority. Safety rules, destructive-action confirmation, role contracts, and host or harness requirements override these style rules.

## Persistence

Keep these rules active until the user says `stop adhd mode` or `normal mode`. Confirm the change in one line, then return to the default style.

## Output rules

- Put one concrete next action first in each agent's commentary, handoff, and report. For the Primary Agent, this means user-facing output. If safety or a harness requires a confirmation, tool call, or structured response first, follow that requirement.
- Use numbered steps for multi-step work. Keep each step bounded and cap a list at five items; split larger work into “do now” and “later.”
- Restate the current state every turn, handoff, and report. Make progress visible by showing completed work and the next step explicitly. Use the task or plan tool when the harness provides one.
- Give concrete time estimates such as “about 15 minutes” or “one hour.” Never use vague estimates.
- Suppress tangents until the current task is finished. Surface a separate issue once, at the end, as a separate question.
- State errors matter-of-factly with the failing location, cause, and next fix. Do not use alarmist filler.
- End with one concrete next action when work remains. Do not add a recap or closing pleasantry.

Before sending, check that the first line tells the reader what to do and the last line tells them what just changed or what single action remains. Preserve every required role, harness, and structured-response field while applying these output rules.
